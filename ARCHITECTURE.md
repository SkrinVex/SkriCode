# SkriPts — Архитектура проекта

## 📋 Обзор проекта

**SkriPts** — это визуальный конструктор интерактивных 2D-симуляций для Android. Проект позволяет создавать игры, анимации и интерактивные приложения без написания кода, используя блочную систему программирования.

### Цели проекта
- ✅ Удобный визуальный редактор блоков
- ✅ Мощная система симуляции с физикой
- ✅ Поддержка событий (тап, удержание, коллизии)
- ✅ Система переменных, таблиц и выражений
- ✅ Экспорт/импорт проектов
- ✅ Работа со спрайтами и текстурами
- ✅ Камера слежения за объектами
- ✅ Джойстик для управления

## ⚙️ Как работает система

### 1. Блочная система

**Блок** — базовая единица программирования. Каждый блок имеет:
- `type` — тип блока (sim_create, if_block, set_var и т.д.)
- `params` — параметры (имя объекта, цвет, позиция и т.д.)
- `children` — вложенные блоки (для условий, циклов, таймеров)

```kotlin
data class BlockDef(
    val id: String,
    val type: String,
    val displayName: String,
    val description: String,
    val category: BlockCategory,
    val params: Map<String, BlockParam>,
    val paramOrder: List<String>,
    val children: Map<String, List<BlockDef>>
)
```

**Категории блоков:**
- 🎮 SIMULATION — создание объектов, движение, удаление
- 🔧 CONTROL — условия, циклы, таймеры
- 📊 DATA — переменные, таблицы, математика
- ⚡ EVENTS — обработка событий (тап, коллизии)
- 🎯 PHYSICS — физический движок

### 2. Движок симуляции (SimEngine.kt)

**Основной цикл:**
```
1. Инициализация (executeSetup)
   - Создание объектов из блоков sim_create
   - Установка начальных параметров
   
2. Игровой цикл (tick)
   - Обработка событий (тап, удержание)
   - Выполнение скриптов
   - Обновление физики
   - Проверка коллизий
   - Обновление джойстиков
   - Обновление камеры
   
3. Рендеринг (Canvas в SimulationScreen.kt)
   - Отрисовка объектов
   - Отрисовка текста
   - Отрисовка спрайтов
   - Отрисовка джойстиков
```

**Физика:**
- Гравитация (настраиваемая для каждого объекта)
- Скорость и ускорение
- Упругость (bounciness)
- Статические объекты (не двигаются)
- Коллизии с границами экрана
- Коллизии между объектами

**Хитбоксы:**
- AUTO — прямоугольник по размеру объекта
- MANUAL — произвольный полигон (рисуется в редакторе)

### 3. Система выражений (ExprEval.kt)

Поддерживает:
- Математические операции: `+`, `-`, `*`, `/`, `%`, `^`
- Сравнения: `==`, `!=`, `>`, `<`, `>=`, `<=`
- Логические: `&&`, `||`, `!`
- Функции: `sin()`, `cos()`, `sqrt()`, `abs()`, `min()`, `max()`, `random()`
- Переменные: `$varName`
- Встроенные константы: `$screenWidth`, `$screenHeight`, `$pi`
- Строковые операции: конкатенация, `length()`, `substring()`

Пример: `$x + sin($time * 0.1) * 50`

### 4. Редактор блоков (EditorScreen.kt)

**Особенности:**
- Drag & drop блоков
- Вложенные блоки (условия, циклы)
- Визуальный редактор выражений
- Color picker для цветов
- Редактор позиций (визуальный выбор координат)
- Редактор хитбоксов
- Сворачивание/разворачивание блоков
- Копирование/вставка блоков

**Специальные блоки:**
- `sim_modify` — универсальное изменение свойств объектов
- `if_block` — условия с ветками then/else
- `for_loop`, `while_loop` — циклы
- `wait` — таймер с вложенными блоками

## 🔧 C++ компонент

### Зачем нужен C++?

**Текущее состояние:** C++ код (`native-lib.cpp`) **НЕ используется** в основной логике приложения.

**История:**
- Изначально планировался для высокопроизводительного выполнения блоков
- Содержит минимальный JSON парсер и интерпретатор блоков
- Поддерживает базовые блоки: print, delay, math, if, repeat, переменные

**Почему не используется:**
- Kotlin-версия (SimEngine.kt) оказалась достаточно быстрой
- Kotlin проще для отладки и расширения
- JNI вызовы добавляют оверхед
- Сложнее интеграция с UI (Compose)

**Возможное будущее использование:**
- Оптимизация физики для сотен объектов
- Параллельная обработка коллизий
- Сложные математические вычисления

## 📊 Производительность

### Текущая производительность

**Хорошо работает:**
- ✅ До 50-100 объектов без физики: 60 FPS
- ✅ До 20-30 объектов с физикой: 60 FPS
- ✅ Сотни блоков в скриптах: без задержек
- ✅ Сложные выражения: мгновенно

**Узкие места:**
- ⚠️ Проверка коллизий: O(n²) для всех пар объектов
- ⚠️ Физика: пересчет для каждого объекта каждый тик
- ⚠️ Рендеринг: Canvas.drawRect/drawText для каждого объекта

### Оптимизации

**Уже реализовано:**
- Пропуск невидимых объектов (visible = false)
- Отключение физики для статических объектов
- Кэширование вычислений выражений
- Ленивая загрузка спрайтов
- Spatial hashing для коллизий (частично)

**Можно улучшить:**
- Quadtree для коллизий → O(n log n)
- Batch rendering для объектов
- Перенос физики в C++
- Использование OpenGL вместо Canvas
- Пул объектов (избежать GC)

### Тесты производительности

**100 объектов без физики:**
- Создание: ~50ms
- Тик: ~5-10ms
- Рендеринг: ~16ms (60 FPS)

**50 объектов с физикой:**
- Тик: ~10-15ms
- Коллизии: ~5-8ms
- Рендеринг: ~16ms

**1000 блоков в скрипте:**
- Выполнение: ~100-200ms (одноразово)
- Не влияет на FPS (выполняется асинхронно)

## 🎯 Система событий

### Типы событий

1. **ScriptEvent.SETUP** — выполняется один раз при старте
2. **ScriptEvent.TICK** — каждый кадр (60 FPS)
3. **ScriptEvent.TAP** — тап по объекту
4. **ScriptEvent.HOLD** — удержание объекта
5. **ScriptEvent.COLLISION** — начало коллизии
6. **ScriptEvent.COLLISION_END** — конец коллизии

### Обработка событий

```kotlin
// В SimEngine.kt
suspend fun tick() {
    // 1. Обработка тап-событий
    processTapEvents()
    
    // 2. Выполнение TICK скриптов
    executeTickScripts()
    
    // 3. Обновление физики
    updatePhysics()
    
    // 4. Проверка коллизий
    checkCollisions()
    
    // 5. Обновление джойстиков
    updateJoysticks()
    
    // 6. Обновление камеры
    updateCamera()
}
```

## 💾 Сохранение данных

### Формат проекта (.skripts)

JSON с шифрованием (опционально):

```json
{
  "id": "uuid",
  "name": "Мой проект",
  "scenes": [
    {
      "id": "scene1",
      "name": "Главная сцена",
      "scripts": [
        {
          "id": "script1",
          "name": "Инициализация",
          "event": "SETUP",
          "blocks": [...]
        }
      ]
    }
  ],
  "variables": [...],
  "tables": [...],
  "sprites": [...]
}
```

### Шифрование (SaveCrypto.kt)

- AES-256-GCM
- Ключ генерируется из пароля (PBKDF2)
- Используется для защиты сохранений переменных/таблиц

## 📈 Масштабируемость

### Текущие ограничения

**Мягкие лимиты (работает, но медленно):**
- 100+ объектов с физикой
- 1000+ блоков в одном скрипте
- 10+ сцен в проекте

**Жесткие лимиты (может крашнуться):**
- 10000+ объектов (OutOfMemoryError)
- Бесконечные циклы (зависание)
- Рекурсивные коллизии (StackOverflow)

### Защита от перегрузки

**Реализовано:**
- Лимит итераций циклов (1000)
- Таймаут выполнения скриптов (5 сек)
- Проверка на бесконечную рекурсию
- Ограничение глубины вложенности (10 уровней)

**Нужно добавить:**
- Лимит объектов на сцене
- Предупреждение о производительности
- Профилировщик (показывать FPS, время тика)
